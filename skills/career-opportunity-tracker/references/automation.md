# 반복 조사 운영

예약 조사 실행이나 자동화 설정 요청에서 읽는다. 이 문서는 재사용할 운영 원칙과 프롬프트 예시다. 개인의 직무 선호·가중치·지원 결과는 개인 프로필과 지정한 기록에 둔다.

## 실행 방식과 기준 정보

- 스킬은 공고 조사·판정·기록 절차를 제공한다. 실행 주기·시간대·실행 대상·알림은 사용하는 앱의 자동화 기능에서 설정한다.
- 긴 상담 대화와 분리해 매번 새 작업으로 실행하는 방식을 권장한다. 사용자가 기존 채팅에서 계속 실행하기를 원하면 그 선택을 따른다. 독립 실행으로 바꾸려면 해당 방식에 대한 사용자 요청을 확인한다.
- 각 실행은 대상 프로필, 최신 이력·증빙, 대시보드·공고·일정 기록에서 필요한 정보를 읽는다. 프로필의 `evidence_sources`에 지정한 개인 근거를 사용하고 충돌하면 최신 사용자 확인과 근거를 대조한다. 이미 확인된 조건을 매번 다시 질문하지 않는다.
- 과거 상담 내용을 읽어야만 실행할 수 있는 프롬프트를 만들지 않는다. 지원 완료·탈락·이름 정정·마감 공고 삭제 같은 일회성 요청을 반복 작업으로 복사하지 않는다.
- 시간대는 사용자가 선택한 값을 명시한다. 실제 확인일·보고 날짜는 실행 시각을 그 시간대로 환산한다. 특정 날짜의 공고나 사용자의 지원 결과를 예약 프롬프트에 고정하지 않는다.
- 새 예약을 만들기 전에 기존 예약을 확인한다. 전환이 가능하면 기존 예약을 갱신하고, 교체가 필요하면 새 설정을 확인한 뒤 이전 예약을 중지해 이중 실행을 피한다. 앱이 제공하는 자동화 기능을 사용한다.

## 매 실행에서 확인할 것

1. **시작 기준:** 실행 날짜·시간대·대상 프로필·저장 위치를 확인하고 최신 개인 사실과 기존 지원 기록을 읽는다. 대상이나 연결에 필요한 정보가 없으면 누락을 밝히고 가능한 조사 범위만 진행한다. 다른 사람의 프로필이나 예시 선호를 대신 사용하지 않는다.
2. **조사와 검증:** 프로필의 탐색 범위를 실제 검색하고 공식 상세·접수 상태·마감을 확인한다. 역할 적합성, 필수조건 충족, 확인이 필요한 조건을 구분한다. 상세 기준은 [지원 자격 확인](eligibility.md)과 [지원 준비](application-prep.md)를 따른다.
3. **중복과 저장:** 공식 URL·회사·지원 단위로 기존 공고를 대조하고 공개 공고 정보만 갱신한다. 확정 마감만 연결된 일정 1건으로 생성·갱신한다. 개인 지원·합불·준비 상태·메모·개인 일정은 보존한다. [지원 기록 운영](notion-workflow.md)의 규칙을 따른다.
4. **날짜별 조사 기록:** 지정된 대시보드에 실행 날짜, 완료 범위, 신규·갱신 건수, 중요 변경, 실제 검색 범위·보류 이유를 남긴다. 같은 날짜에 수동 조사나 재실행 기록이 있으면 기존 내용과 대조해 추가 조사·수정임을 구분하고 중복 등록을 피한다.
5. **최종 보고:** 신규 후보와 주요 변경, 아직 지원하지 않은 적합 후보의 임박 마감, 저장 성공·실패, 대시보드 링크를 보고한다. 신규 주 추천이 없으면 없다고 명시한다. 알림 여부와 응답 형식은 앱의 규칙과 사용자의 알림 설정을 따른다.

긴 실행의 요약이나 중단 후에는 이번 실행 날짜와 완료·미완료 범위를 복원한다. 읽기·검색·개인 조건 확인만 끝내고 일일 조사가 완료됐다고 답하지 않는다. 쓰기 결과가 모호하면 기존 항목을 다시 조회해 중복을 피하고, 권한·연결 오류가 계속되면 가능한 조사 결과와 미완료 범위를 보고한다.

## 완료와 실패를 구분하기

| 확인된 상태 | 판단과 보고 |
| --- | --- |
| 예약이 활성 상태로 저장됨 | 설정 완료. 실제 실행 성공은 아직 확인 전이다. |
| 예약 시각에 시작 기록이 없음 | 예약 미실행 여부를 점검한다. 앱의 실제 실행 이력 없이 원인을 단정하지 않는다. |
| 검색·읽기만 하고 종료됨 | 조사 미완료. 마지막 완료 단계와 검증·저장·보고 중 빠진 단계를 밝힌다. |
| 조사 결과는 있으나 Notion 쓰기 실패 | 조사 결과를 채팅에 제공하고 저장 실패·부분 성공을 구분한다. 저장했다고 주장하지 않는다. |
| 날짜별 보고 저장·최종 응답이 있으나 알림을 못 받음 | 조사 실행과 알림 전달을 분리해 알림 설정·전달 상태를 확인한다. |
| 신규 주 추천이 없고 실제 검색 범위·보류 이유를 기록함 | 조사를 완료했다면 정상적인 '신규 없음' 결과다. 검색하지 않은 상태를 신규 없음으로 처리하지 않는다. |

이 구분은 작업 절차다. 별도의 자동 감시·재시도 프로그램이나 실행 보장을 제공하는 것은 아니다.

## 자동화 요청 예시

개인 프로필·증빙·Notion 연결이 준비된 뒤 다음처럼 요청할 수 있다. 오전 9시와 Asia/Seoul은 예시이며 개인 설정에 맞게 바꾼다.

```text
매일 오전 9시, Asia/Seoul 기준으로 맞춤 공고를 조사해줘.
이 상담 채팅을 이어 쓰지 않고 매번 별도 작업으로 실행하도록 설정해줘.
설치된 career-opportunity-tracker와 내가 지정한 개인 프로필을 사용해줘.
아래 반복 조사 프롬프트를 적용하고 기존 예약이 있으면 중복 생성하지 말고 변경해줘.
```

앱에서 실제 예약을 설정한 결과와 실행 대상·시각·시간대·활성 상태를 확인한다. 지원되는 앱이라면 실행 결과를 받는 알림 설정도 확인한다. 앱·도구의 실제 기능을 확인하지 않고 예약을 만들었다고 말하지 않는다.

## 반복 조사 프롬프트 예시

아래 `<개인 프로필의 절대 경로>`를 본인 파일로 바꾸고, 그 프로필에 `evidence_sources`와 `notion` 저장 위치를 지정한다. 개인 사실·가중치·지원 결과를 프롬프트에 복사해 고정하지 않는다. 이 예시는 예약 내용이며 시간·주기·알림은 앱에서 별도로 설정한다.

```text
이번 독립 실행의 현지 날짜를 기준으로 현재 지원 가능한 맞춤 채용공고를 조사한다.

기준 정보:
- 설치된 career-opportunity-tracker의 SKILL.md와 반복 조사 운영 문서를 읽는다.
- 개인 프로필: <개인 프로필의 절대 경로>
- 프로필의 evidence_sources에서 최신 개인 사실·경험·사용자 확인 조건을 읽는다.
- 프로필의 notion에 지정한 대시보드·공고·일정 데이터 소스를 읽는다.
- 확인일·보고 날짜·마감 비교는 프로필에 지정한 시간대를 사용한다.
- 과거 상담 채팅을 이어서 읽거나, 과거의 지원 결과·정정·삭제 요청을 재실행하지 않는다.

수행할 일:
1. 최신 스키마·기존 공고·일정을 읽고 이미 지원했거나 전형 종료된 건을 대조한다.
2. 개인 프로필의 서로 다른 탐색 범위를 함께 실제 검색한다. 개인 필수조건·선호·가중치를 사용하며 예시 프로필의 기준을 자동 적용하지 않는다.
3. 회사 공식 채용 페이지와 주요 플랫폼을 검색하고 중요한 후보의 공식 상세·현재 접수·마감을 확인한다. 플랫폼 중복·재공고·공채 지원 단위를 대조한다.
4. 역할 적합성과 필수조건 충족을 별도로 판단한다. 중요한 미확인 조건은 주 추천과 분리하고, 공식 미기재와 조회 실패를 구분한다. 이미 확인된 개인 조건은 재사용한다.
5. 적합한 신규는 최대 5개로 하되 개수를 채우지 않는다. 경험 연결·실제 실행 범위·필수조건·근무조건·마감·공식 링크·확인일·준비 과제를 정리한다.
6. 중복 없이 공고 정보를 저장하고 공식 확정 마감만 연결된 일정 1건으로 생성·갱신한다. 개인 지원 상태·지원일·전형 단계·합불·준비 상태·메모·개인 일정은 보존한다. 일일 조사로 기록을 삭제하지 않는다.
7. 대시보드에 이번 현지 날짜의 조사 기록을 남긴다. 같은 날짜 보고가 있으면 추가·수정 범위를 구분한다. 기존 보고만 보고 오늘 조사를 끝내지 않는다.
8. 신규·갱신 건수, 우선 검토할 1~2개와 이유, 지원하지 않은 적합 후보의 3일 이내 마감, 중요 변경, 저장 성공·실패와 대시보드 링크를 최종 보고한다. 신규 주 추천이 없으면 없다고 밝히고 실제 검색 범위와 보류 이유를 적는다.

완료 기준:
검색·공식 검증·기존 항목 대조·저장·날짜별 조사 기록·최종 보고까지 완료한다.
요약이나 중단 뒤에는 이번 실행 날짜와 미완료 단계로 돌아간다.
시작·검색·개인 조건 확인만으로 완료 처리하지 않는다.
저장 실패 시 조사 결과를 채팅으로 제공하고 실패·부분 성공을 명시한다.
예약에 없는 지원서 제출·타인 연락·기록 삭제·공개 게시를 수행하지 않는다.
```

## 공개 저장소와 개인 설정

- 공개 버전에는 이 운영 원칙과 빈칸이 있는 예시만 둔다. 실제 개인 프로필·Notion 주소·지원 이력·인증정보·앱의 자동화 설정 파일을 올리지 않는다.
- Git 업데이트는 설치된 스킬과 앱의 예약 설정에 자동 적용되지 않는다. 스킬을 업데이트할 때 개인 프로필을 보존하고, 예약 내용도 바꿀 필요가 있으면 앱에서 별도로 갱신한다.
- 예약 프롬프트는 최신 로컬 스킬을 읽도록 작성해 공통 조사 절차의 중복을 줄인다. 개인 기준을 바꾸면 개인 프로필·지정 근거 자료에 반영하고, 지원 결과는 지원 대시보드에 반영한다.
