# 지원 기록 운영

## 읽기와 중복

선택한 프로필의 대시보드·공고·일정 데이터 소스를 사용한다. 쓰기 전에 최신 페이지·스키마·기존 행을 읽는다. 다른 사람의 프로필에 저장 위치가 없으면 다른 사람의 대시보드를 대신 사용하지 않는다.

Notion 연결 도구를 우선한다. 실제 fetch의 컬럼명·선택지를 사용하고, 날짜는 `date:마감일:start`처럼 확장된다. SQL 결과의 링크·서식 생략은 손상의 증거가 아니다. 긴 텍스트 수리 시에는 페이지를 fetch한다. rows 모드가 지원되지 않으면 현재 스키마 기반 SQL 또는 저장된 뷰를 쓴다.

회사·지원 직무·공식 URL/식별자로 기존 행을 찾는다. 추적 파라미터·플랫폼 마감 차이로 중복 생성하지 않는다. 공채 직무 분리와 재공고 여부는 실제 지원 단위·차수로 판단한다.

## 정보 보존

공고 필드 예: `공고`, `회사`, `직무·팀`, `공식 링크`, `모집 상태`, `자격요건`, `근무·고용조건`, `적합성·주의점`, `확인 근거`, `공고 확인일`, `마감일`, `분야`, `직접 개발`, `우선순위`.

개인 필드 예: `지원 상태`, `지원일`, `전형 단계`, `서류 결과`, `면접 결과`, `최종 결과`, 메모·체크리스트·개인 일정.

- 새 후보의 지원 상태·서류/면접/최종 결과는 **미확인**. 실제 지원일·단계·면접일은 만들지 않는다.
- 공개 조사로는 공고 정보만 갱신한다. 개인 기록·메모·준비 항목을 덮어쓰지 않는다.
- 공식 현재 모집과 확정 마감을 우선하고, 출처 충돌을 남긴다. 모집 불명확은 `재확인 필요`, 접수 종료는 `마감`. 모집 마감은 개인 불합격이 아니다.
- 일일 조사에서는 닫힌 행을 삭제하지 않고 보존한다. 사용자의 명시적 정리 요청은 아래 절차로 처리한다.

## 자격·제출 요건·준비 관리

기존 스키마에 맞춰 다음 필드를 재사용하고, 개선 요청이 허가된 경우에만 부족한 필드를 추가한다. 매 조사마다 스키마를 바꾸지 않는다.

- `지원 자격 판정`: 미확인 / 조건 확인 필요 / 확인된 조건 충족 / 조건 차이 / 지원 불가
- `지원 자격 근거`: 공고 필수조건·출처·확인일과 개인 사실의 출처, 불충족/확인할 점. [지원 자격 확인](eligibility.md)을 따른다.
- `제출 서류·전형`: 회사가 실제 요구한 제출물·문항·분량·전형·출처와 미확인 사항
- `경험 연결·준비 포인트`: 사실 근거가 있는 직무별 사례, 필수 기술 등 차이와 준비 제안
- `서류 준비 상태`: 미확인 / 요건 정리 / 초안 작성 / 검토 중 / 제출본 확정

자격 근거에는 필요한 개인 정보만 남기고 민감한 증빙 전체를 복사하지 않는다. 자격 판정은 공고와 확인된 프로필을 대조한 파생 정보다. 둘 중 하나가 바뀌면 다시 평가하되 개인 전형 결과를 변경하지 않는다. 모집 종료와 지원 불가는 서로 다른 상태다.

공개 조사에서 제출 요건과 새로운 준비 제안을 갱신할 수 있으나, 사용자의 기존 경험 연결·준비 메모·체크리스트는 보존하고 새 근거만 덧붙인다. `서류 준비 상태`는 개인 필드다. 신규 후보는 미확인, 기존 빈 값은 미평가이며 일괄 진행 상태를 추정하지 않는다. 실제 작성 요청을 수행했을 때만 작업한 범위를 반영한다. `제출본 확정`을 지원 완료로 해석하지 않는다.

신규 조건 확인 후보는 주 추천과 분리한다. 사용자의 기록 요청이 있거나 기존 후보를 재평가하는 경우에는 판정·이유를 기록하되 지원 일정/기록은 추정하지 않는다. 필수조건 불충족 신규 후보는 별도 기록 요청 없이 등록하지 않는다.

## 마감·개인 일정

공식 확정 마감에는 해당 공고와 연결된 `지원 마감` 일정 **1건**을 생성/갱신한다. 기존 일정의 날짜·관계가 맞으면 새로 만들지 않는다. 직무별 공고라면 각 지원 건에 1건씩 연결할 수 있다.

일정 속성 예: `일정`, `공고`(관계), `종류`, `날짜`, `진행 상태`, `결과`, `확인 근거·메모`.

공고·일정은 한국 채용이면 Asia/Seoul로 맞춘다. 반환된 UTC를 변환해 비교한다. 날짜만 확인되면 임의 23:59를 붙이지 않고, 상시·미정에 날짜를 넣지 않는다. **11/23 00:00은 11/22가 끝나는 자정**이며 11/23 23:59와 다르다.

공개 결과 발표일과 개인 확정 일정을 구분한다. 개인 면접·과제·발표 기록을 공고 조사로 바꾸거나 중복 생성하지 않는다. 사용자가 실제 일정을 알려주면 해당 지원 건에 연결한다.

## 지원·합불 반영

회사명만 주어지면 기존 지원 건과 단계를 읽어 대상을 찾는다. '둘 다'는 해당 회사의 확인된 두 지원 건에 반영한다. 대상을 특정할 수 없으면 필요한 부분만 질문한다.

'서류 탈락'은 서류 불합격·전형 종료·최종 불합격으로 기록할 수 있다. 단계 없는 '탈락'은 최종 불합격·전형 종료를 반영하되 서류/면접 단계가 기록으로 명확하지 않으면 추정하지 않는다. 합격은 단계 합격과 최종 합격을 구분한다. 지원일·면접일을 결과 수신일로 채우지 않는다.

## 요청받은 마감 공고 정리

'바빠서 지원 못했다, 기간 지난 공고 삭제'는 **마감됐고 지원 이력이 없는 공고** 정리로 해석한다. 현재 삭제 요청이 이전 보존 지시보다 우선한다. 이미 허가한 범위를 다시 승인받지 않는다. 일회성 정리를 매일 자동 삭제 정책으로 확대하지 않는다.

1. 최신 행과 현재 현지 시각을 읽고 정확한 마감 또는 확인된 종료로 만료를 판정한다. 날짜만 있으면 그 날짜가 끝난 후 만료다. 오늘 밤 마감 전·상시·날짜 미상·단순 재확인 필요는 삭제하지 않는다.
2. 미확인/미지원 성격인 행을 찾되 지원일·지원 완료·진행 단계·합불·실제 개인 일정이 있는 행은 보존한다. 모순되는 개인 기록은 추정 삭제하지 않는다. 미확인을 미지원으로 상태 변경할 근거로 쓰지 않는다.
3. 확인된 대상만 **복구 가능한 휴지통**으로 이동한다. 해당 공고에만 연결된 지원 마감 일정도 정리하되 공유 일정·개인 전형 일정·다른 공고의 오래된 일정까지 범위를 넓히지 않는다.
4. 결과에서 성공 여부를 확인하고 공고명·공고 수·일정 수를 보고한다. 영구 삭제·휴지통 비우기는 하지 않는다. 대상이 없으면 없다고 알린다.

## 실패 대응

성공/실패 항목을 구분한다. 생성 호출의 결과가 모호하면 다시 조회해 중복 생성을 막는다. 연결·권한 오류가 계속되면 조사 결과를 채팅으로 제공하고 저장 실패를 명시한다. 저장했다고 주장하지 않는다.
