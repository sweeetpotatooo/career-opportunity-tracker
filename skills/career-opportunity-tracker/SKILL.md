# 취업 공고 조사·지원 관리

공통 조사 절차와 개인의 선택 기준을 분리한다. 실행할 때 대상자의 프로필을 읽고 적용한 기준을 설명한다. 특정 직무·스택·산업을 모든 사람에게 일괄 우선하지 않는다.

## 프로필 선택

- 기본 개인 프로필은 포함하지 않는다. [예시 프로필](profiles/example.yaml)의 구조를 참고해 `profiles/local/<프로필명>.yaml`을 만들거나 사용자가 지정한 프로필을 읽는다. 예시 파일은 구조 설명용이며 실제 선호로 자동 적용하지 않는다.
- 대상이 여러 명이면 누구의 프로필인지 확인한다. 새 프로필은 현재 요청에서 알려진 경험·조건을 채우고 중요한 누락만 질문한다. 다른 사람의 경력·선호·Notion 저장 위치를 복사 적용하지 않는다.
- 프로필의 필수조건·가중치를 변경하거나 다른 기준으로 비교할 때 [평가 방식](references/ranking.md)을 읽는다. 한 공고에 대한 관심을 전체 선호 변경으로 확대하지 않는다.

## 요청 범위

- **맞춤 조사:** 프로필의 탐색 범위를 실제 검색하고 현재 기록과 비교한다. 일일 조사 요청에서는 지정된 대시보드 저장을 포함한다.
- **특정 공고 검토:** 해당 공고·회사 자료를 확인한다. 등록 요청이 있을 때 기존 항목을 갱신하거나 추가한다.
- **지원 준비:** 공고의 실제 제출 요건을 정리하고 확인된 경험을 직무별 근거로 연결한다. [지원 준비](references/application-prep.md)를 따른다.
- **지원·합불·일정 반영:** 해당 개인 지원 건만 수정한다. 불필요하게 새 공고를 검색하지 않는다.
- **마감 공고 정리:** 명시적으로 요청받은 범위를 복구 가능한 휴지통으로 옮긴다.
- **기준 조율:** 검색하지 말라는 요청이면 먼저 기준을 논의한다. 합의된 지속적 변경은 해당 프로필에 반영한다.

Notion을 읽거나 쓸 때 [지원 기록 운영](references/notion-workflow.md)을 읽고 프로필의 저장 위치를 사용한다. 스킬 호출 자체는 지원서 제출, 타인에게 메시지 전송, 자동화 생성·변경, 다른 사람의 데이터 공유를 허가하지 않는다.

## 공통 조사 품질

1. 기업 공식 채용 사이트와 주요 플랫폼에서 찾는다. 플랫폼 목록은 확장 가능하며 LinkedIn도 포함한다. 프로필에 서로 다른 역할군이 있으면 함께 검색·비교한다.
2. 중요한 후보는 공식 상세 본문·현재 접수 여부·마감일을 직접 확인한다. 검색 요약의 D-day나 상시 표시만 믿지 않는다. 필요하면 브라우저로 렌더링된 내용을 읽는다.
3. 공식 URL/식별자와 회사·지원 직무로 중복을 합친다. 재공고는 채용 차수·식별자·내용을 확인한다. 공채는 실제 지원 직무가 확인되면 지원 단위로 나눈다.
4. 추천·신규 등록 전에 [지원 자격 확인](references/eligibility.md)으로 필수조건을 대조한다. 불충족은 제외하고, 중요한 미확인은 조건 확인 대상으로 분리한다. 프로필에서 명시한 경력 예외만 보조 후보로 남긴다. 역할 적합성과 지원 조건 충족 여부를 분리한다. AI 활용이 필수 경력·학위·어학·기술 경험을 충족한다고 추정하지 않는다. 교육과정·콘텐츠 '개발'을 소프트웨어 코딩으로 읽지 않는다.
5. 공채·수시라는 이름보다 실제 지원 단위, 제출 서류·문항·분량·전형을 확인한다. 주요 후보는 [지원 준비](references/application-prep.md)에 따라 필요한 준비를 제시한다.
6. 현재 모집을 확인한 후보와 마감·미확인 후보를 구분한다. 새 후보·중요 변경을 우선하며 이전 보류 후보도 가능한 범위에서 점검한다.

## 보고

프로필 기준으로 적합한 신규 후보를 최대 5개 추천하고 개수를 채우지 않는다. 표에는 회사·직무·팀, 핵심 문제와 실제 실행 기회, 해당 인물 경험과의 연결, 직접 구현/AI·노코드/개발팀 협업 범위, 선호 도메인 관련성, 필수조건, 고용형태·근무지·마감·공식 지원 링크·확인일을 담는다. 후보가 하나면 공통 조건을 표 아래 묶어도 된다.

지원 자격 판정·근거와 실제 제출 요건을 함께 표시한다. `조건 확인 필요`는 현재 지원 가능한 주 추천과 섞지 않는다.

**원하는 일과의 적합성**과 **현재 도전할 때의 차이·준비 과제**를 나눠 설명한다. 적용한 가중치·중요 불확실성을 밝히고 오늘 검토할 1~2개를 고른다. 이미 지원했거나 전형 종료된 건에 재지원을 권하지 않는다. 신규 주 추천이 없으면 없다고 말하고 실제 검색 범위·중요 변경만 보고한다.

저장 성공·실패를 구분하고 대시보드 링크를 제공한다. 자동화로 호출되면 호스트의 heartbeat 응답·알림 규칙을 따른다. 실행 자체나 확인일 갱신만을 중요한 변화로 포장하지 않는다.
